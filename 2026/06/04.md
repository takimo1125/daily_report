### Go
#### 1. 並行処理（Concurrency）
##### 1.1 ゴルーチン (Goroutine)
Goランタイムが管理する軽量スレッド。`go` 文を付与することで関数を並行（Parallel/Concurrent）に実行できる。
######特徴
- 非常に軽量（スタックメモリは2KB程度から開始し、必要に応じて自動で拡張・縮小）
- OSスレッド（1〜2MB）よりはるかに低コスト
- 1つのアプリケーションで数千〜数万個のゴルーチンを同時実行可能
- Goランタイムが独自のスケジューラ（$M:N$ スケジューリング）で管理
#### ゴルーチンの終了制約
- `main` ゴルーチンが終了すると、他のすべてのゴルーチンも強制終了する
- ゴルーチン自体は自身の完了を待つ仕組みを持たない
- **解決策:** `time.Sleep` で待つ（非推奨）、または **チャネル** や `sync.WaitGroup` で同期する
#### 制約
- 共有メモリの安全性は保証されないため、チャネルやミューテックスによる明示的な同期が必要
#### 💡 例文：ゴルーチンの起動
```go
package main
import (
	"fmt"
	"time"
)
func sayHello(name string) {
	for i := 0; i < 3; i++ {
		fmt.Printf("Hello, %s!\n", name)
		time.Sleep(100 * time.Millisecond)
	}
}
func main() {
	// ゴルーチンとして並行実行
	go sayHello("Goroutine")
	// メインゴルーチンでの実行
	sayHello("Main")
}
```

##### 1.2 チャネル (Channel)
ゴルーチン間で安全にデータをやり取り（通信）するための仕組み。データ型を指定して生成する。
###### 基本操作
- 送信・受信演算子（`<-`）を使用する
- デフォルト（バッファなし）では、送信側と受信側の双方の準備ができるまで処理がブロック（停止）する
- これにより、明示的なロックなしで同期が可能
###### チャネルのブロッキング条件
| 方向 | ブロック条件 |
|------|------------|
| 送信側 | 受信側がデータを読み取る準備ができるまでブロック |
| 受信側 | 送信側がデータを書き込むまでブロック |
###### チャネルの方向性
| 型 | 説明 |
|----|------|
| `chan T` | 双方向 |
| `chan<- T` | 送信専用 |
| `<-chan T` | 受信専用 |
> **利点:** 関数のインターフェースを明確にし、誤用（受信専用なのに送信するなど）をコンパイル時にチェックできる。
###### チャネルのクローズ
- `close(ch)` でこれ以上値を送信しないことを示す
- クローズ済みのチャネルへの送信や、重ねてクローズを行うと**パニック**（強制終了）する
- クローズされたチャネルからの受信は、型ごとの初期値（ゼロ値）が返る
- `v, ok := <-ch` の2値受信で、チャネルがクローズされたか判定可能（`ok` が `false` ならクローズ状態）
- `for v := range ch` ループを使うと、クローズされるまで自動で受信を繰り返し、クローズ時にループを抜ける
> **注意:** クローズは必須ではない（GCが回収する）。`range` ループを終わらせたい場合などに送信側の責任で行う。
#### 💡 例文：チャネルの基本とクローズ処理
```go
package main
import "fmt"
// 送信専用チャネルを受け取る関数
func generateNumbers(ch chan<- int) {
	for i := 1; i <= 3; i++ {
		ch <- i // 送信
	}
	close(ch) // 送信完了後にクローズ
}
func main() {
	ch := make(chan int) // バッファなしチャネルの生成
	go generateNumbers(ch)
	// rangeループでクローズされるまで受信
	for num := range ch {
		fmt.Println("Received:", num)
	}
}
```
##### 1.3 バッファ付きチャネル
内部にキュー（メモリバッファ）を持つチャネル。
###### 特徴
- バッファが満杯（フル）になるまでは、送信側はブロックされずに処理を継続できる
- `len(ch)` で現在の要素数、`cap(ch)` でバッファ容量を取得可能
###### ブロッキング条件
| タイミング | ブロック条件 |
|-----------|------------|
| 送信時 | バッファが満杯（`len == cap`）のとき |
| 受信時 | バッファが空（`len == 0`）のとき |
###### 使い分けの基準
| 種別 | 用途 |
|------|------|
| バッファなし（デフォルト） | 厳密な同期、一対一のタイミング合わせが必要な場合 |
| バッファ付き | 送受信の「一時的な速度差」やバースト的な負荷を吸収したい場合 |
###### バッファサイズの選び方
| サイズ | 用途 |
|--------|------|
| なし | デフォルトの選択肢 |
| 小さい（1〜10） | 一時的な速度差の吸収、メモリ効率重視 |
| 大きい（100〜1000） | バースト負荷への対応 |
> **注意:** バッファサイズは同時実行数ではない。過度なバッファは「待機バッファ問題（メモリの無駄遣いやバグの隠蔽）」を招く。
###### 💡 例文：バッファ付きチャネル
```go
package main
import "fmt"
func main() {
	// 容量2のバッファ付きチャネル
	ch := make(chan string, 2)
	ch <- "A"
	ch <- "B" // バッファが2個埋まったため、これ以上は受信側がいないとブロックする
	fmt.Println(<-ch)
	fmt.Println(<-ch)
}
```

##### 1.4 Select文 (select)
複数のチャネル操作のうち、準備ができたものをどれか1つ実行する制御構造。
###### 特徴
- 複数の `case` が同時に準備完了している場合、**ランダムに1つが選択される**（公平性の保証、特定のチャネルの飢餓状態/スターベーションを防ぐ）
- すべての `case` が準備できていない場合はブロックして待つ
- タイムアウトやキャンセル（Context）、複数ソースからのイベント集約によく使われる
###### default ケース（ノンブロッキング select）
- どの `case` も準備できていない場合、ブロックせずに即座に `default` が実行される
- チャネルのポーリング（差し迫ったデータがあるかどうかの確認）に利用
###### 💡 例文：selectによるタイムアウト処理
```go
package main
import (
	"fmt"
	"time"
)
func main() {
	ch := make(chan string)
	go func() {
		time.Sleep(2 * time.Second) // 重い処理をシミュレート
		ch <- "処理完了"
	}()
	select {
	case res := <-ch:
		fmt.Println("結果:", res)
	case <-time.After(1 * time.Second): // 1秒でタイムアウト
		fmt.Println("エラー: タイムアウトしました")
	}
}
```

#### 2. 同期処理とデータ保護
##### 2.1 sync.Mutex (ミューテックス)
複数のゴルーチンが同時に共有メモリ（変数など）へアクセスすることで発生する競合状態（データレース / Race Condition）を防ぐための排他制御機構。
> **問題点:** `counter++` のような単純なコードも、CPUレベルでは「読み込み」「加算」「書き込み」の複数命令に分かれているため、対策しないとデータが失われる。
###### 基本メソッド
| メソッド | 説明 |
|---------|------|
| `Lock()` | ロックを取得。他が取得中の場合は空くまで待機 |
| `Unlock()` | ロックを解放。必ず `Lock()` をしたゴルーチンが呼び出す必要がある |
###### Deferでの確実な解放
ロック取得直後に `defer m.Unlock()` を記述することで、関数内に複数の `return` パスやエラー処理があっても、解放漏れ（デッドロックの原因）を確実に防げる。
###### 💡 例文：sync.Mutex による安全なカウンタ
```go
package main
import (
	"fmt"
	"sync"
)
type SafeCounter struct {
	mu    sync.Mutex
	value int
}
func (c *SafeCounter) Inc() {
	c.mu.Lock()
	defer c.mu.Unlock() // 関数を抜けるときに必ずアンロックされる
	c.value++
}
func main() {
	var wg sync.WaitGroup
	counter := SafeCounter{}
	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			counter.Inc()
		}()
	}
	wg.Wait()
	fmt.Println("Counter:", counter.value) // 確実に1000になる
}
```

##### 2.2 sync.RWMutex (読込・書込ミューテックス)
読み込み（Read）と書き込み（Write）でロックを分ける、より細かな排他制御機構。
###### 仕様
| メソッド | 説明 |
|---------|------|
| `RLock()` / `RUnlock()` | 読み込みロック。読み込み同士であれば複数ゴルーチンが同時アクセス可能。書き込みはブロックされる |
| `Lock()` / `Unlock()` | 書き込みロック。他のすべての読み込み・書き込みをブロック（完全な排他） |
> **用途:** 読み込み頻度が非常に高く、書き込み頻度が低いデータ（キャッシュ、設定ファイルなど）の保護に最適。パフォーマンスが向上する。

##### 💡 チャネルとミューテックスの使い分け
| 手法 | 使うべき場面 |
|------|------------|
| **チャネル** | データの所有権を渡す場合、データの通信・通知が主目的である場合（「通信によってメモリを共有する」というGoの思想）。迷ったらまずチャネルを検討する |
| **ミューテックス** | 単なる状態、構造体の中身、共有キャッシュなどの「共有メモリの保護」そのものが目的である場合 |

#### 3. 標準パッケージ
##### 3.1 os パッケージ
オペレーティングシステム（OS）の機能（ファイルI/O、環境変数、プロセス管理など）へアクセスする。
###### ファイル読み込み
| 関数 | 説明 |
|------|------|
| `os.Open()` | ファイルを開く。戻り値のエラーチェックは必須。開いた後は `defer file.Close()` で確実に閉じる |
| `os.ReadFile()` | ファイル全体を一括でメモリ（`[]byte`）に読み込む。内部で自動的に Open/Read/Close を行うため、小さいファイル向け |
###### ファイル書き込み
| 関数 | 説明 |
|------|------|
| `os.WriteFile()` | データの塊（`[]byte`）とパーミッション（例: `0644`）を指定し、一括でファイルへ書き込む。既存ファイルは上書きされる |
| `os.Create()` | 新規ファイルを作成（既存なら空にする）し、段階的にデータを書き込めるファイルオブジェクト（`*os.File`）を返す。大きいファイルや動的生成向け |
###### エラー種類の判定
| 関数 | 説明 |
|------|------|
| `os.IsNotExist(err)` | ファイルが存在しないエラーか確認 |
| `os.IsPermission(err)` | 権限エラーか確認 |
#### 💡 例文：osパッケージによるファイルの読み書き
```go
package main
import (
	"fmt"
	"os"
)
func main() {
	filename := "test.txt"
	content := []byte("Hello, Go OS package!")
	// 1. 一括書き込み
	err := os.WriteFile(filename, content, 0644)
	if err != nil {
		fmt.Println("書き込みエラー:", err)
		return
	}
	// 2. 一括読み込み
	data, err := os.ReadFile(filename)
	if err != nil {
		if os.IsNotExist(err) {
			fmt.Println("ファイルが存在しません")
		}
		return
	}
	fmt.Println("ファイル内容:", string(data))
}
```

##### 3.2 io パッケージ（Reader / Writer インターフェース）
あらゆるデータストリーム（ファイル、ネットワーク、メモリ等）を抽象化するGoの最重要インターフェース群。
#### io.Reader
- `Read(p []byte) (n int, err error)` のメソッドを持つ
- データ元から引数のスライス `p` へデータを読み込み、読み込んだバイト数 `n` とエラー（末尾に達したら `io.EOF`）を返す
- **実装例:** `os.File`, `strings.Reader`, `bytes.Buffer`, `net.Conn`
###### io.Writer
- `Write(p []byte) (n int, err error)` のメソッドを持つ
- `[]byte` のデータをターゲットに書き込む
- **実装例:** `os.File`, `bytes.Buffer`, `net.Conn`, `os.Stdout`（標準出力）

##### 3.3 bufio パッケージ
I/O処理のパフォーマンスを向上させるため、内部にバッファ（緩衝用メモリ）を挟むパッケージ。
> **利点:** 1バイトや1行ごとの細かいディスク/ネットワークアクセスをまとめ、システムコール回数を減らすことで性能向上。行単位・単語単位のパースが容易。
#### bufio.Scanner の分割モード（SplitFunc）
| モード | 説明 |
|--------|------|
| `bufio.ScanLines`（デフォルト） | 行ごと |
| `bufio.ScanWords` | スペース区切りの単語ごと |
| `bufio.ScanRunes` | UTF-8文字ごと |
| `bufio.ScanBytes` | バイトごと |
#### 💡 例文：bufio.Scannerによる行毎の読み込み
```go
package main
import (
	"bufio"
	"fmt"
	"strings"
)
func main() {
	input := "第一行\n第二行\n第三行"
	// strings.Reader は io.Reader インターフェースを満たす
	reader := strings.NewReader(input)
	scanner := bufio.NewScanner(reader)
	// 行ごとにループ
	for scanner.Scan() {
		fmt.Println("Line:", scanner.Text()) // Text() で文字列として取得
	}
}
```

##### 3.5 strconv パッケージ
文字列（`string`）と基本データ型（`int`, `float`, `bool` など）の相互変換を行う。
###### 文字列 → 数値・他（エラーハンドリング必須）
| 関数 | 説明 |
|------|------|
| `strconv.Atoi(s)` | `string` から `int` への簡易変換 |
| `strconv.ParseInt()` | 基数を指定して整数に変換 |
| `strconv.ParseFloat()` | 浮動小数点数に変換 |
| `strconv.ParseBool()` | 真偽値に変換 |
###### 数値・他 → 文字列
| 関数 | 説明 |
|------|------|
| `strconv.Itoa(i)` | `int` から `string` への簡易変換 |
| `strconv.FormatInt()` | 整数を文字列に変換 |
| `strconv.FormatFloat()` | 浮動小数点数を文字列に変換 |
| `strconv.FormatBool()` | 真偽値を文字列に変換 |
> **注意:** 変換できない文字列（例: `"abc"` を数値化）を渡すとエラーを返すため、必ずエラーチェックを行う。
###### 💡 例文：strconvによる変換とエラーハンドリング
```go
package main
import (
	"fmt"
	"strconv"
)
func main() {
	// 文字列 -> 数値
	strNum := "123"
	num, err := strconv.Atoi(strNum)
	if err != nil {
		fmt.Println("変換失敗:", err)
		return
	}
	fmt.Println("数値:", num)
	// エラーになるケース
	_, err = strconv.Atoi("123-xyz")
	if err != nil {
		fmt.Println("期待通りのエラー:", err)
	}
}
```

##### 3.7 encoding/json パッケージ
データのシリアライズ（構造体 → JSON文字列：`Marshal`）およびデシリアライズ（JSON文字列 → 構造体：`Unmarshal`）を担う。
> **用途:** REST APIのリクエスト/レスポンス、設定ファイル（`config.json`）、DB保存用。言語に依存しない標準フォーマット。
###### 💡 例文：JSONの相互変換
```go
package main
import (
	"encoding/json"
	"fmt"
)
type User struct {
	Name string `json:"name"` // 構造体タグでJSONのキー名を指定
	Age  int    `json:"age"`
}
func main() {
	// 構造体 -> JSON (Marshal)
	u := User{Name: "Taro", Age: 25}
	jsonData, _ := json.Marshal(u)
	fmt.Println("JSON String:", string(jsonData))
	// JSON -> 構造体 (Unmarshal)
	jsonInput := `{"name":"Jiro","age":30}`
	var u2 User
	_ = json.Unmarshal([]byte(jsonInput), &u2) // ポインタを渡す
	fmt.Printf("Struct: %+v\n", u2)
}
```

#### 4. テスト (Testing)
Goは標準ライブラリ（`testing` パッケージ）だけで完全にテストをサポートしている。
###### 特徴
- 外部フレームワーク（JUnitやRSpecのようなもの）が不要。シンプル。
- **命名規則:** テスト対象が `main.go` なら、テストファイル名は必ず `main_test.go` にする
- **テスト関数の署名:** `func TestXxxx(t *testing.T)` で記述。`Xxxx` は対象の関数名など（先頭は大文字）
###### テストの実行コマンド
| コマンド | 説明 |
|---------|------|
| `go test` | カレントディレクトリのテストを実行 |
| `go test ./...` | サブディレクトリを含むすべてのパッケージのテストを実行 |
| `go test -v` | 詳細な進捗・ログ（`t.Log`）を出力 |
| `go test -run TestName` | 特定のテスト関数のみ実行 |
###### アサーション（判定）の思想
- Goには `assert()` 関数が存在しない
- 通常の `if` 文で条件チェックを行い、満たさない場合は `t.Errorf()` や `t.Fatalf()` を呼び出して明示的に失敗を報告する
- **利点:** テストコードが通常のGoコードと同じになり、明示的で制御フローが追いやすい
###### 💡 例文：ユニットテストの書き方
**対象コード（`math.go`）:**
```go
package mymath
func Add(a, b int) int {
	return a + b
}
```

#### 5. GoでのWebアプリケーション開発
##### 5.1 なぜGoでWeb開発をするのか
| 理由 | 説明 |
|------|------|
| **標準ライブラリの充実** | `net/http`, `encoding/json`, `database/sql` が強力なため、サードパーティ製フレームワークがなくてもフル機能のWeb APIを構築可能 |
| **圧倒的なパフォーマンス** | コンパイル言語としての高速性と、ゴルーチンによる並行処理、高いメモリ効率 |
| **抜群の保守性** | 静的型付け、明示的なエラーハンドリング、シンプルな言語仕様 |
| **容易な運用・デプロイ** | 依存関係をすべて含んだ「1つのバイナリファイル」にコンパイルされるため、Docker環境などへのデプロイが極めて容易（軽量なScratchイメージが使える） |
| **実務採用実績** | Kubernetes, Docker, etcd, Terraform, Prometheus などのインフラコア技術はすべてGo製 |

##### 5.2 net/http パッケージの構成要素
| 要素 | 説明 |
|------|------|
| `http.Server` | ポート番号、ハンドラ、読み込み/書き込みのタイムアウト（`ReadTimeout`, `WriteTimeout`）などの設定を持つサーバー本体 |
| `http.Request` | クライアントからの要求データ。メソッド（GET, POST）、URL、ヘッダー、ボディ（`Body`）、フォームデータ（`Form`, `PostForm`）を含む |
| `http.ResponseWriter` | クライアントへ返すレスポンスを組み立てるインターフェース。ヘッダーの設定、ステータスコード（`WriteHeader`）、ボディの書き込み（`Write`）を行う |
| マルチプレクサ（ルーター） | リクエストのパス（URL）に応じて、適切なハンドラ関数へルーティング（振り分け）する |
#### 💡 例文：シンプルなHTTPサーバーの構築
```go
package main
import (
	"fmt"
	"net/http"
)
func helloHandler(w http.ResponseWriter, r *http.Request) {
	// レスポンスヘッダーの設定
	w.Header().Set("Content-Type", "text/plain; charset=utf-8")
	// ステータスコードとボディの書き込み
	w.WriteHeader(http.StatusOK)
	fmt.Fprint(w, "Hello, World! GoのHTTPサーバーです。")
}
func main() {
	// ルーティングの登録
	http.HandleFunc("/hello", helloHandler)
	fmt.Println("Server starting on :8080...")
	// サーバーの起動
	if err := http.ListenAndServe(":8080", nil); err != nil {
		panic(err)
	}
}
```

##### 5.3 database/sql パッケージ（データベース接続）
特定のデータベース（MySQL, PostgreSQL, SQLiteなど）に依存しない、共通の抽象SQLインターフェースを提供する。
###### 特徴
| 特徴 | 説明 |
|------|------|
| **ドライバー方式** | 各データベース用の「ドライバー」をブランクインポート（`import _ "..."`）して差し替えるだけで、同じコードのまま別DBに対応可能 |
| **接続プール管理** | `sql.DB` オブジェクトは自動的に内部で接続（コネクション）をプール・再利用するため、開発者が手動で接続を管理する必要がなく、高効率・安全 |
| **スレッドセーフ** | 複数のゴルーチンから同時に安全にアクセス可能 |
###### 主要な型
| 型 | 説明 |
|----|------|
| `sql.DB` | データベースハンドル（接続プールを保持） |
| `sql.Tx` | トランザクション |
| `sql.Rows` | 複数行のクエリ結果（ループと `.Next()`、`.Scan()` でデータを抽出） |
| `sql.Row` | 1行のみのクエリ結果（`.Scan()` で即抽出、データがない場合は `sql.ErrNoRows` エラーが発生） |
| `sql.Result` | 命令（INSERT/UPDATE/DELETE）の結果（影響を受けた行数やラストインサートIDの取得） |
