## 取り組んだ課題一覧
- AWS と Terraformで実現するInfrastructure as Code

## わかったこと
### VPC

**CIDR Blockとは**
CIDR BlockはIPアドレスの範囲を表します。
- 例: `10.0.0.0/16`
- 利用可能IP数: 65536個

**サブネットに分割して利用する**
- 例:
  ```text
  VPC
  10.0.0.0/16
  ├─ Public
  │  10.0.1.0/24
  └─ Private
     10.0.2.0/24
  ```

---

### サブネット

サブネットはVPCを分割したネットワークです。

**種類:**
- **Public Subnet**
  - インターネットへ接続可能
  - 例: Webサーバー, ALB, NAT Gateway
- **Private Subnet**
  - インターネットから直接アクセス不可
  - 例: RDS, 内部API, Batch

---

### ルートテーブル

通信先によって転送先を決定します。

**例:**
| 送信先 | 転送先 |
| :--- | :--- |
| 10.0.0.0/16 | local |
| 0.0.0.0/0 | igw |

- **意味:** VPC内通信は `local` へ、それ以外は `Internet Gateway` (`igw`) へルーティングします。

---

### セキュリティグループ

AWSの仮想ファイアウォールです。

**特徴:**
- **ステートフル:** 戻り通信（レスポンス）は自動的に許可されます。
- 例:
  - **Inbound:** 80, 443
  - **Outbound:** All (すべて許可)

---

### プレフィックスリスト

複数のIPアドレス範囲の管理を簡単にする仕組みです。

**構成例:**
```text
Office
├─ 1.1.1.0/24
├─ 2.2.2.0/24
└─ 3.3.3.0/24
```

**Security Groupでの利用例:**
```hcl
prefix_list_ids = [
  aws_ec2_managed_prefix_list.office.id
]
```

---

### RDSパラメータグループ

データベースの設定値をまとめて管理します。
- 例: `max_connections`, `log_statement`, `character_set`
- ※ 設定を変更すると、DBの再起動が必要になる場合があります。

---

### オプショングループ

データベースの追加機能（プラグイン等）を有効化します。
- 例: OracleやSQL Serverの特定機能など、一部機能はオプショングループで有効化します。

---

### RDS削除防止

```hcl
deletion_protection = true
```
- **効果:** `terraform destroy` や AWSコンソールからの誤った削除操作を防ぎます。

---

### tfstate

Terraformが最も重要視する状態管理ファイルです。

**保存内容:**
- リソースID
- 属性値
- 依存関係

**例:**
```json
{
  "resources": [...]
}
```

---

### tfstateをGit管理しない理由

**理由:**
1. **機密情報が含まれる** (パスワードやキー情報などが平文で入るため)
2. **競合しやすい** (複数人で同時に編集するとコンフリクトする)
3. **破損すると危険** (状態が壊れると既存リソースの管理ができなくなる)

※ 実務では **S3 + DynamoDB Lock** を使ってリモートバックエンドで管理するのが一般的です。

---

### Terraform Import

既存のクラウド環境にあるリソースを、Terraformの管理下に置くためのコマンドです。

**例:**
```bash
terraform import aws_instance.web i-123456789
```

**流れ:**
1. `import` コマンドを実行する
2. コード（定義）を作成する
3. `terraform plan` で差分がないか確認する
4. `terraform apply` で同期する

---

### depends_on

リソースの作成順序を明示的に指定します。
※ 通常は不要です。Terraformは参照関係から依存関係を自動的に判定します。

**自動依存の例:**
```hcl
subnet_id = aws_subnet.public.id
```
この場合、サブネットが先に作られてから他のリソースが作られるよう自動で判定されます。

**手動で明示的に指定する例:**
```hcl
depends_on = [
  aws_iam_role.example
]
```

---

### count と for_each の違い

#### count (番号管理)
```hcl
count = 3
```
- **生成されるリソース名:** `server[0]`, `server[1]`, `server[2]`
- **注意点:** 途中の要素（例: `server[1]`）を削除すると、それ以降のインデックスがズレてしまい、意図しない再作成が発生します。

#### for_each (キー管理)
```hcl
for_each = {
  dev  = "t3.micro"
  prod = "t3.large"
}
```
- **生成されるリソース名:** `server["dev"]`, `server["prod"]`
- **メリット:** 特定のキーだけを安全に削除・追加できるため、実務ではこちらが推奨されます。

---

### lifecycle

#### prevent_destroy
```hcl
lifecycle {
  prevent_destroy = true
}
```
- 本番環境のDBなど、誤って削除されては困る重要なリソースでよく利用します。

#### ignore_changes
```hcl
lifecycle {
  ignore_changes = [
    tags
  ]
}
```
- AWSコンソールなどTerraform外部から手動で変更される項目（タグなど）の差分検知を無視したい場合に指定します。

---

### terraform graph

リソースの依存関係を視覚化します。

```bash
terraform graph
```
- **出力のイメージ:** `VPC` → `Subnet` → `EC2`
- 大規模な環境でリソース間のつながりを調査する際に便利です。

---

### For式

リストやマップの要素をループ処理で変換します。

**List変換の例:**
```hcl
[
  for name in var.users :
  upper(name)
]
```
- **結果:** `["TARO", "JIRO"]`

**フィルタ（条件付き抽出）の例:**
```hcl
[
  for n in var.numbers :
  n
  if n > 10
]
```

---

### 三項演算子

条件によって設定する値を切り替えます。
```text
条件 ? 真の場合の値 : 偽の場合の値
```

**例:**
```hcl
var.env == "prod" ? "t3.large" : "t3.micro"
```

**実務での利用例:**
```hcl
instance_type = (
  var.env == "prod"
  ? "t3.large"
  : "t3.micro"
)
```
