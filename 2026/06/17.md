## わかったこと
### Next.js レンダリングと App Router メモ

### Next.js とは

JavaScript は命令的（Imperative）な UI 開発が中心であり、直感的に理解しづらい部分があります。

React は宣言的（Declarative）な UI ライブラリです。

- JSX という拡張構文を利用する
- 「どう描画するか」ではなく「どうあるべきか」を記述する

Next.js は React の便利な仕組みを組み込んだフルスタックフレームワークです。

### Next.js の特徴

- サーバーサイドレンダリング対応
- App Router
- ファイルベースルーティング
- ページごとにレンダリング方式を選択可能

### レンダリング方式

#### CSR（Client Side Rendering）

クライアント側で JavaScript が HTML を構築する。

#### SSR（Server Side Rendering）

リクエストごとにサーバーで HTML を生成する。

#### SSG（Static Site Generation）

ビルド時に HTML を生成する。

#### ISR（Incremental Static Regeneration）

ビルド時に HTML を生成し、指定時間ごとに再生成する。

### ビルド

開発時に書いたコードを本番環境向けに変換・最適化する処理。

- トランスパイル
- 圧縮
- バンドル
- 最適化

### ハイドレーション

サーバーで生成された静的 HTML に JavaScript の機能を追加して操作可能にする仕組み。

### React Server Components（RSC）

サーバー上でコンポーネントをレンダリングする仕組み。

App Router ではデフォルトで Server Component になる。

#### Client Component

`'use client'` を付与する。

#### Server Component

サーバー上で実行される。

### Static Rendering

ビルド時点で HTML を生成する方式。

### RSC Payload

React Server Components のレンダリング結果を保持するデータ。

含まれる内容

- コンポーネントツリー
- Client Component 情報
- Server Component 情報

### Dynamic Rendering

リクエストごとに HTML を生成する方式。

### App Router のレンダリング

App Router はデフォルトで Static Rendering。

Dynamic API を利用すると Dynamic Rendering になる。

例

- cookies()
- headers()
- searchParams

### revalidatePath

ページを再生成する API。

例

`revalidatePath('/dashboard')`

### 開発モードと本番モード

開発モードでは Server Component が毎回再実行される。

本番環境ではキャッシュや静的生成が利用されるため、結果が異なる場合がある。
