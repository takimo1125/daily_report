## 取り組んだ課題一覧
- AWSでDockerを本番運用！AmazonECSを使って低コストでコンテナを運用する実践コース

## わかったこと
### ECS

- サーバーを1台ずつ管理する必要がない
- 管理用サーバーが不要
- ブラウザから設定・管理が可能
- 運用コストが低い

### Kubernetes

- 主に大規模サービスで利用される
- Google の多くのサービスで利用されている

### インフラで大切なこと

- シンプルであること
- 費用が読みやすいこと
- 構築が楽であること

### Fargate

- サーバーレスなコンテナ実行環境
- EC2 のようにサーバー管理が不要
- タスクを管理する単位を「サービス」という
- データベースは外部サービスに任せる構成が一般的

### Docker が必要な理由

- 環境構築時間の短縮
- アプリ実行環境の品質向上
- 自動化ツールとの相性が良い

### Docker の特徴

- Docker は設計図どおりに環境を作成する
- 必ず同じコンテナ環境を作成できる

### 従来の仮想環境

- 人の手が介在するため、設定ミスが起こりやすい

### そもそもコンテナとは

- 隔離されたパッケージ化された実行環境
- サーバー上に隔離されたアプリケーション実行空間を作れる技術

### Docker で本番運用するメリット

- 品質向上
- 構築コスト削減
- 人に依存しない
- インフラのコード化ができる

### Docker を使うことによってできること

- インフラをコードとして管理できる

### Docker の最大のメリット

- インフラをコード化できる
- ファイルを読むだけで構成が分かる
- 誰でも同じコンテナ環境を作れる
- 環境の受け渡しが簡単

### Dockerfile

- Docker イメージを作成するための設定ファイル
- サーバー上で実行する設定をコードで管理できる
- 設定などを自動で行える

### Docker Run

- Docker イメージがローカルにない場合、Docker Hub から自動取得する

### コンテナに入るとは

- コンテナのコマンドラインにアクセスすること
- コマンドライン経由でコンテナを操作できる

### Docker Exec

- 起動中のコンテナに対してコマンドを実行する
- コンテナに入らずにコマンド実行も可能
- `-it` オプションを使うとコンテナ内部に入れる

### Docker Build

- Dockerfile から Docker イメージを生成する

### Dockerfile のメリット

- Docker イメージをコード化できる
- ファイルを読むだけで構成が分かる
- オリジナルイメージを作成できる
- 設定ファイルなども変更できる

### ECS 用のロール

- ECS 用の IAM ロールを作成する必要がある
- 作成しないと AWS リソースへアクセスできない

### AWS のリージョンと AZ

- リージョン：AWS の世界地域単位
- AZ（Availability Zone）：データセンター単位
- 複数の AZ を利用することで可用性を高められる

### AWS CLI

- AWS をコマンドラインから操作するためのツール

### ECR

- Docker イメージをアップロードして管理するサービス

### 水平スケーリング

- サーバー台数を増やして負荷分散すること
- Elastic File System（EFS）を利用すると共有データを管理できる

### Fargate の弱点

- 実体となるサーバーが見えない
- EC2 のように直接サーバーへアクセスできない
- Docker コマンドを直接実行できない
- デバッグがしづらい
- 初心者にはイメージしづらい

### ECS 構築の流れ

1. ECS クラスター用の VPC を作成
2. コンテナ配置の設計
3. Docker イメージを作成
4. ECR にアップロード
5. ECS に Pull してデプロイ

### Session Manager

- Session Manager を利用してデバッグが可能

### ロードバランサー

- ロードバランサーを使用して負荷分散を行う
- ターゲットグループに ECS タスクを登録する

### ECS のサービス作成

- ECS でサービスを作成してタスクを管理する

### ECS のオートスケーリング

- Fargate の場合、自動でスケーリング可能
- CPU 使用率が上がるとタスク数を増やせる
