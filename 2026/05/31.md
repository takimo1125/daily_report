### Terraform 詳細解説

#### Terraformとは

Terraformは HashiCorp が開発した Infrastructure as Code (IaC) ツールである。

インフラ構成をコードとして管理し、自動的にクラウド環境へ反映できる。

メリット

- インフラ構成をコード管理できる
- Gitで履歴管理できる
- レビュー可能
- 再現性が高い
- 手作業によるミスを削減できる
- CI/CDへ組み込み可能

#### Terraformの構成要素

##### Provider

Terraformから各種クラウドサービスを操作するためのプラグイン。

例

```hcl
provider "aws" {
  region = "ap-northeast-1"
}
```

代表的なProvider

- AWS
- Azure
- Google Cloud
- GitHub
- Datadog
- Kubernetes

##### Resource

実際に作成されるクラウドリソース。

```hcl
resource "aws_s3_bucket" "sample" {
  bucket = "sample-bucket"
}
```

##### Data Source

既存リソースを参照する。

```hcl
data "aws_caller_identity" "current" {}
```

##### Variable

外部から値を受け取る。

```hcl
variable "environment" {
  type = string
}
```

利用

```hcl
tags = {
  Environment = var.environment
}
```

##### Local

内部変数。

```hcl
locals {
  project = "sample"
}
```

##### Output

結果出力。

```hcl
output "bucket_name" {
  value = aws_s3_bucket.sample.id
}
```

#### Terraform State

Terraformは管理対象をStateファイルに保存する。

```text
terraform.tfstate
```

保持内容

- 作成済みリソース
- リソースID
- 属性情報
- 差分計算情報

##### ローカルState

```text
terraform.tfstate
```

個人検証向け。

##### リモートState

AWSではS3を利用することが多い。

```hcl
terraform {
  backend "s3" {
    bucket = "terraform-state"
    key    = "prod/terraform.tfstate"
    region = "ap-northeast-1"
  }
}
```

メリット

- チーム共有
- バックアップ
- CI/CD利用可能

#### State Lock

複数人が同時実行するとState破損の可能性がある。

DynamoDBでロックする。

```hcl
terraform {
  backend "s3" {
    bucket         = "terraform-state"
    key            = "prod/terraform.tfstate"
    dynamodb_table = "terraform-lock"
  }
}
```

#### Terraform Workflow

一般的な実行順序

```text
terraform fmt
↓
terraform init
↓
terraform validate
↓
terraform plan
↓
terraform apply
```

#### terraform fmt

コード整形。

```bash
terraform fmt
```

CIで利用

```bash
terraform fmt -check
```

#### terraform init

初期化処理。

実行内容

- Provider取得
- Module取得
- Backend初期化

```bash
terraform init
```

```bash
terraform init -no-color
```

#### terraform validate

構文チェック。

```bash
terraform validate
```

JSON形式

```bash
terraform validate -json
```

#### terraform plan

変更内容確認。

```bash
terraform plan
```

内容

- 作成
- 更新
- 削除

の差分を確認する。

実行結果例

```text
+ create
~ update
- destroy
```

Plan保存

```bash
terraform plan -out=tfplan
```

#### terraform apply

環境へ反映。

```bash
terraform apply
```

Plan利用

```bash
terraform apply tfplan
```

自動承認

```bash
terraform apply -auto-approve
```

#### terraform destroy

環境削除。

```bash
terraform destroy
```

自動承認

```bash
terraform destroy -auto-approve
```

#### Module

Terraformコードを部品化する仕組み。

```hcl
module "network" {
  source = "./modules/network"
}
```

メリット

- 再利用可能
- 保守性向上
- 標準化

#### Workspace

環境切り替え機能。

作成

```bash
terraform workspace new dev
```

切替

```bash
terraform workspace select prod
```

確認

```bash
terraform workspace list
```

#### Terraform CI/CD

典型例

```text
Pull Request
↓
terraform fmt
↓
terraform validate
↓
terraform plan
↓
Slack通知
↓
承認
↓
terraform apply
```

#### GitHub ActionsでのTerraform実行例

```yaml
- uses: actions/checkout@v4

- uses: hashicorp/setup-terraform@v3
  with:
    terraform_version: 1.12.0

- run: terraform init

- run: terraform validate

- run: terraform plan
```

#### ベストプラクティス

- StateはS3で管理
- DynamoDBでLock管理
- Provider Version固定
- Module化する
- 本番Apply前にレビュー
- OIDC認証を利用
- Access KeyをSecretsへ保存しない

#### AWSでTerraform管理可能な代表サービス

- VPC
- EC2
- IAM
- S3
- CloudFront
- Route53
- Lambda
- ECS
- EKS
- RDS
- DynamoDB
