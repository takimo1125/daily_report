## わかったこと
### Next.js

Reactをベースにしたフルスタックフレームワーク。

### CSR
従来のReact方式。ブラウザでHTMLを生成。

メリット
- 高度なインタラクション
- サーバー負荷が低い

デメリット
- JavaScriptが大きい
- 初期表示が遅い
- SEOに弱い

### SSR
サーバーでHTMLを生成し、その後Hydrationを行う。

メリット
- 初期表示が速い
- SEOに強い

デメリット
- サーバー負荷が高い

### SSG
ビルド時にHTMLを生成。

### ISR
一定時間ごとに静的ページを再生成。

### App Router
appディレクトリを利用する新方式。コンポーネント単位でレンダリングを制御できる。

### Server Component
基本はこちらを利用する。PrismaなどのDB処理が可能。

### Client Component
必要最小限で利用する。Prismaは使用不可。

### データ取得
GETはServer Component。
POST/PUT/DELETEはServer ActionsまたはRoute Handlers。

### Route Handlers
外部API公開やHeader/Cookie制御向け。

### Server Actions
DB更新などNext.js内で完結する処理向け。
Client/Server Component双方から呼び出せる。

### Suspense
非同期Server Componentをラップし、読み込み中のUIを表示する。

### shadcn/ui
Card、Button、Dialogなどを提供するUIライブラリ。

### Composition Pattern
Server Componentの子としてClient Componentを配置する設計。
